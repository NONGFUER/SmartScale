# 2026-07-30

## SettingsDialog 版本更新检测逻辑重构（OTA 检测简化）
- 移除 SettingsDialog 中基于 `OtaService.state` 的多分支过渡态显示（"检查中..."/下载中%/校验中/待安装/安装中）。
- 检测结果为二元：`OtaService.updateAvailable`（true=有新版本 / false=无新版本）。状态文本直接绑定 `updateVersionText`，仅显示"发现新版本 Vx"或"已是最新版本"，杜绝界面卡在"检查中"。
- `onCheckFinished` 失败静默处理：不覆盖既有结果、不显示错误态；成功无更新→"已是最新版本"。
- 下载按钮固定"立即下载"，点击 `otaDialog.open()` + `OtaService.startDownload()`（内部自守卫）；下载/校验/安装进度全部由 OtaUpdateDialog 承载。
- 打开时查询守卫改为 `otaInProgress()`（下载/校验/安装/待安装态跳过），不再耦合 Checking 态。
- OtaService 状态机本身保留（下载/刷写流程仍需 Downloading/Verifying/Installing 等态驱动 OtaUpdateDialog），仅 UI 不再暴露"检查中"。

## 版本更新行显示规则补充（本地比云端新时）
- 云端版本 ≤ 本地（如本地 2.13.3.30 > 云端 2.13.3.26）时，不再显示"已是最新版本"，直接显示云端版本号（小写 v 前缀，如 `v2.13.3.26`），不弹下载按钮。
- `onCheckFinished` 用 `version` 参数（始终=云端版本）去 `V` 前缀后展示；有更新才显示"发现新版本 vX"。`OtaService.latestVersion` 仅在有更新时更新，但 QML 直接用信号里的 `version` 参数，故本地更新时也能显示云端版本。
