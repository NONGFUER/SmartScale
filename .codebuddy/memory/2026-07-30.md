# 2026-07-30

## WiFi 连接模块缺陷修复（三轮）
文件：`src/services/NetworkManagerService.cpp/.h`、`src/ui/components/WifiPasswordDialog.qml`

### 第一轮（三个缺陷）
1. **密码本地缓存（断线重连免重复输入）**：新增 `getCachedWifiPassword(ssid)` / `cacheWifiPassword(ssid,password)`（Q_INVOKABLE），持久化到 `~/.config/SmartScale/wifi_passwords.conf`（QSettings INI，键 `wifi/<ssid>`）。成功连接时缓存密码；`WifiPasswordDialog.openFor(ssid)` 自动填充缓存密码。明文存储（与项目既有 base64 明文约定一致，有泄露风险）。
2. **密码错误提示**：认证失败（`Secrets were required`/`no valid connections`）原代码**静默重连**用同样错误密码并 `return`，永不 emit `wifiConnectionFailed`，导致前端永久卡"连接中"且后台无限重试（缺陷2、3根因）。已改为：删除认证失败的旧连接配置 → 清除该 SSID 错误密码缓存 → `setWifiStatus(Error)` + emit `wifiConnectionFailed("密码错误或认证失败，请重新输入")`，前端据此显示红字错误并解除加载态、按钮复用。
3. **前后端状态同步/解除 UI 死锁**：修复后密码验证失败不再静默建连，前端回到可输入的初始态。

### 第二轮（三个新缺陷）
1. **第一次输错密码显示"创建连接失败+专业术语"**：`nmcli connection add` 对密码格式（PSK ≥8 位等）做校验时返回非零并带原始属性错误信息。`onWifiConnectionAdded` 失败分支原样透出 `errOutput.left(60)`。**修复**：改为 `setLastError("连接失败，请重试")`，隐藏 nmcli 原始输出。`onWifiConnectFinished` 通用 else 分支同样清理。
2. **第一次成功后无论输入什么都能连接**：原 `connectWifi` 的**复用路径**直接 `connection up existingConn` 而**不传用户输入的密码**，NM 用自己保存的密码完成认证，因此任意输入都"成功"。**修复**：仅当 `password` 与本地缓存密码一致（开放网络除外）时才复用；否则删除旧连接并用本次输入的密码两步法重建，用户输入的密码真正参与认证。
3. **重复创建同名网络（截图一堆 1Phone）**：根因有两个 —— (a) `findExistingConnection` 用 `connType == "wifi"` 匹配，NM 实际 TYPE 是 `802-11-wireless`，导致**永远找不到**已有连接、每次都新建；(b) 第一轮认证失败分支虽不再重连，但未做同 SSID 去重。**修复**：
   - `findExistingConnection` 的 TYPE 匹配改为同时接受 `802-11-wireless` 和 `wifi`。
   - 新增 `findAllConnectionsForSsid(ssid)` 返回该 SSID 所有 wifi 连接名；`deleteConnectionsByName(names)` 批量删除（一次 nmcli 调用）。
   - `connectWifi` 重写：先查所有同名连接 → 多于一个时保留活动连接（否则第一个）、删除其余 → 再决定复用/重建。每次连接后每个 SSID 最多一个连接，下次连接到该 SSID 会自动清理历史同名连接。

**关键原则**：`connection up` 复用路径不会把用户输入的密码传给 NM，因此不能借此校验密码；只有两步法 `connection add ... wifi-sec.psk <password>` + `connection up` 才会让用户输入参与 NM 真实认证。
