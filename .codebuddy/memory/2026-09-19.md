## 澄清并调整：内嵌资源的释放落点（用户质疑"不是释放到 build 目录么"）

用户在示例日志里看到 `已释放内嵌资源: …/.cache/smartscale/embedded/AI/rec.onnx`，以为应该释放到 `<APP_DIR>`（`build/`）下。

当时实现（09-19 早先版本）优先级：
1. `<APP_DIR>/AI`（或 `keyboard_styles`）已有且尺寸一致 → 直接用；
2. 否则释放到 `<AppPaths::cacheDir()>/embedded/<子目录>`（选缓存目录的理由是"必然可写"）；
3. 都没有 → 返回空、调用方回退告警。

**已改为（用户预期 + 与随包部署布局一致）** `src/utils/EmbeddedAssets.cpp::resolveDir()`：
1. 设备目录已有且**尺寸与内嵌副本一致** → 直接用（零拷贝，行为不变）；
2. 否则**优先释放到设备目录 `<APP_DIR>/<子目录>`**（`QDir::mkpath` 后还需 `QFileInfo(releaseDir).isWritable()` 判定，mkpath 成功≠可写）；
3. 设备目录不可写（如属 root）→ 退回 `<AppPaths::cacheDir()>/embedded/<子目录>`；
4. 都没有 → 返回空，调用方回退并告警。

同步更新了 `EmbeddedAssets.h` 的文档注释与 `kReleaseRoot` 的注释（"释放位置（可写目录）"→"缓存目录下的兜底释放子目录"）。`read_lints` 全绿。

**修正后的预期日志**（存量设备第一次 OTA 后）：

（若 `<APP_DIR>` 不可写，才会看到 `.cache/smartscale/embedded/...` 的路径。）

注意：释放到 `<APP_DIR>` 后，下次启动会命中第 1 条（文件齐备 + 尺寸一致）→ 不再复制，也不再有 `已释放` 日志。
