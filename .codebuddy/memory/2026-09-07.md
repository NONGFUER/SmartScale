## 树莓派硬件平台勘察（PI 5）
- 主板：Raspberry Pi 5 Model B Rev 1.1；`/boot/firmware/config.txt` 仅一行 `dtoverlay=imx519`（摄像头）。
- 供电/电流：Pi 5 无旧式 `usb_max_current` config.txt 项，电流管理在 DA9091 PMIC。查看实时电流：`vcgencmd pmic_read_adc`（各轨 A current/V），输入电压 EXT5V_V≈4.83V，BATT_V 无电池≈2.7V。供电状态 `vcgencmd get_throttled`=0x0 正常。功耗采样 `vcgencmd power_monitor <V轨> <A轨> start|stop`。
- EEPROM（bootloader，非 BIOS、无交互界面）：当前配置含 `PSU_MAX_CURRENT=5000`（5A/25W，官方上限）、`BOOT_ORDER=0xf14`、`POWER_OFF_ON_HALT=0`、`DISABLE_HDMI=1`、`USB_MSD_DISCOVER_TIMEOUT=1500`。
  - 查看：`vcgencmd bootloader_config`（免 root）/ `sudo rpi-eeprom-config`。
  - 编辑（改 PSU_MAX_CURRENT 等）：`sudo rpi-eeprom-config --edit`，保存写回、重启刷入。
  - 导出/应用：`--out boot.conf` / `--apply boot.conf`；固件升级 `sudo rpi-eeprom-update`。

## 4G 故障排查：有信号(CSQ)但无法联网
- 4G 链路架构：ASR ML307B（USB 2ecc:3012）RNDIS → **eth1**（NM 连接"有线连接 1"，autoconnect+DHCP auto）；AT 口 option 枚举 ttyUSB0/1/2，app 动态探测到 ttyUSB2 常驻轮询 AT+CSQ（信号格）。**信号(CSQ, RF)与数据链路(eth1 carrier/DHCP)解耦**，有信号≠能上网。
- **`quectel-cm.service` 是错误拨号器**：ExecStart=/home/sjwu/quectel-cm/quectel-CM -s 3gnet。ML307B 非高通 QMI（无 cdc-wdm/wwan0），qmidevice_detect failed→exit255，systemd 每 10s auto-restart（restart counter 50+）。应 `sudo systemctl disable --now quectel-cm`。
- 2026-09-07 现场：开机 23:42:35 eth1 carrier connected → NM 自动激活"有线连接 1"→DHCP 192.168.0.100 成默认路由；**23:43:45(启动后~70s) eth1 carrier 掉 → unavailable**，之后再未恢复；23:46:43 起 quectel-cm 开始 10s 循环。修复路径：先停 quectel-cm，再 `nmcli con up "有线连接 1"`（模块 RNDIS 可自动拨号，需 carrier 回来）；仍不通则查模块/APN/AT 激活。掉线 ~70s 疑与上层网络模式切换或模块掉线有关，未定位。
- 排查命令备忘：`vcgencmd` 无电流参数；`nmcli device status`；`journalctl -u quectel-cm -n`；`journalctl -u NetworkManager | grep eth1`；`lsusb -t` 看 rndis_host/option 绑定。

## 4G 故障更新（用户澄清，同晚）
- **23:43:45 的 eth1 carrier 掉线 = 用户手动在 App 关 4G**（非故障）。当前 AppSettings.ini：`cellularEnabled=false`、`networkMode=0`=WifiOnly、`wifiEnabled=true`。
- App 4G 控制实现（NetworkManagerService.cpp）：开=`enableCellular→sudo -n ip link set eth1 up`（依赖 NM auto-activate+DHCP），关=`ip link set down`；非 QMI/AT 拨号。metric/默认路由策略在 setNetworkMode 全开分支（延迟 8s 应用）。
- **"开 4G 就没网"重大嫌疑=网段冲突**：eth1 RNDIS DHCP 到 **192.168.0.100（网关 192.168.0.1，即 ML307B 模块内部 DHCP 默认网段）与现场 WiFi(192.168.0.74/24, 网关 192.168.0.1) 完全同段**。全开/优先4G 时 eth1 成默认路由，同网段+同网关路由打架/模块实际数据不通 → 断网；关 4G 走 WiFi 即恢复。其他设备无此问题(未插该模块/网段不同)。判定方法：复现开 4G 后 `ip route` + `ping -I eth1 223.5.5.5`。
- 串口端口实况：ttyUSB0=DIAG 日志口(二进制流非 AT)，ttyUSB1 无响应，**ttyUSB2=AT 口但被 app 独占（二次 open 报 EBUSY，疑 option 口单开），无法外插查询**。模块 APN/注册状态待查（CGDCONT/CEREG）。quectel-cm.service 结论不变：应 disable（ASR 模块非高通 QMI）。
