- **OTA 取消下载 bug 修复**：用户反馈"下载中点取消后，再点立即下载没有进度条"。根因：cancelDownload/onDownloadFinished 取消分支回 Idle，而 startDownload 守卫仅放行 HasUpdate/Failed → Idle 被静默拒绝（UI 按钮 visible 绑的是 updateAvailable 标志仍为 true，所以按钮还在但点了无效）。修复：取消下载后一律回 HasUpdate（更新信息仍有效，允许再次下载），两处（onDownloadFinished OperationCanceledError 分支 + cancelDownload 无 reply 分支）。教训：状态机中"取消"语义应回到操作前的等待态而非初始态，尤其当入口守卫不含初始态时。

- **串口打不开排查（/dev/ttyAMA0 "Permission error while locking the device"）**：注意这**不是**访问权限问题（那报 Permission denied），而是 QSerialPort 申请独占锁失败。两类成因：① OTA 演练时旧进程未完全退出仍持锁 → 新进程拉起报锁错；② 异常强杀残留 UUCP 锁文件 `/var/lock/LCK..ttyAMA0`（属主 root、非 root 运行无法清理）。诊断：sudo lsof /dev/ttyAMA0 看占用、ps aux|grep appSmartScale 查双进程、ls -l /dev/ttyAMA0 查权限(dialout 组)。处理：双进程则 sudo pkill -9 -x appSmartScale；无进程但仍报错则 sudo rm -f /var/lock/LCK..ttyAMA0。根治：改 scripts/apply_update.sh 第6步（停应用后轮询等待进程真正退出，最多15s再 SIGKILL，回滚兜底路径同样加等待），防双进程抢串口锁。脚本在 qrc 内，需 make -j1 重新打包资源才生效到下次升级。
