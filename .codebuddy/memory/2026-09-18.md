## 样式修复后首次实测暴露的两个识别层问题（已修）

实测日志：`[HWR] 提交识别，笔画数: 6` → `[PPOCR] 置信度过低，丢弃识别结果: "鸡" 0.269694` → `[HWR] 未识别出结果`；候选栏只有 `火 ・ 一 ，`。

### 问题 1：置信度阈值把"对的"丢了（已修）
`kMinConfidence` 0.30 → **0.02**（仅过滤纯噪声）。手写体置信度远低于印刷体（正确字常只有 0.2~0.4），阈值必须压到只剩"均匀分布噪声"级别。新增 `kLowConfidenceHint = 0.45f`：低于它只打日志提示，**结果仍然上屏**（预编辑 + 候选纠正）。另加 `kMinInkSize = 6px` 误触过滤（外接框过小的点击不进识别，配合原有的"点数<2 直接丢弃"）。

### 问题 2：候选生成只看"概率峰值那一个时间步"（已修）
旧实现取峰值步 top-5 → 手写时模型常在某些步纠结偏旁，峰值步的正确字可能完全不出现（实测写"鸡"时峰值步 top 全是 火/一/，）。
**改为跨时间步聚合每个类别出现过的最大概率再排序**（`classBest[c] = max_t p[t][c]`，跳过 blank，按概率降序取 top-N，去重），CTC 最优路径结果仍放首位（其重复项先剔除再 prepend）。候选数 5 → **8**（IM 的 `kMaxCandidates = 8`，HwrTestDialog 同步改 8）。
Python 复现新旧算法对比（同一份 logits）：
- 鸡：旧 `鸡 d ，` → 新 `鸡 鸦 鸭 鸥 鸣 鸿 鸤`
- 火：旧 `' . ,` → 新 `火 北 水 次 业 化 比`
- 鱼：旧 `鱼 $ B` → 新 `鱼 。 魚 . 色 」`

- 手写链路已完全打通（样式 → 采点 → 识别 → 预编辑/候选 → 落字）。

## 识别率调优（第三轮）

### 消融实验结果（重要：直觉被否掉）

## 关于"是否要换模型"的结论（给用户的决策框架）

用户 `AI/rec.onnx` **任何情况下都不删**（既是回退也是多字/印刷体场景的主引擎）。三个层次：
- **层次 0（不动模型）**：现状 + 已实现的 TTA 融合 + 食材词表后处理纠偏。食材名场景收益常常最大，成本最低。
- **层次 1（drop-in 换文件，零改代码）**：`PP-OCRv5_mobile_rec` → `PP-OCRv5_server_rec`（同 `[1,3,48,W]` 输入、同 ppocrv5_dict、同 CTC 18385 类）⇒ **只换 rec.onnx 文件即可**，精度提升明显；代价是推理变慢数倍（需实测，估计 15ms → 80~150ms）、体积升到几十 MB；可把 TTA 3 路降到 1~2 路补偿。需要自己用 paddle2onnx 转换或找现成 ONNX。
- **层次 2（真换引擎，改 `PpocrRecognizer` 内部）**：CASIA-HWDB 系**单字**模型（如 HCCR-CNN9Layer：96×96 灰度、**分类头 3926 类**、非 CTC）⇒ 预处理尺寸/通道、解码、词表全变；不支持多字连写/标点/英文（需双引擎调度：单字走 HWR、其余回退 PP-OCRv5）；数据集许可为"研究免费、商用需授权"，现成可商用 ONNX 需自行训练或核实来源。属最后手段。
推荐顺序：0 →（若不够）1 →（仍不够）2；先用板端参数扫描拿到真实数据再决策。

### 第二次问题：历史重量/称重数字/单价标签全空白（缺 import SmartScale）
现象：页面上所有走 `WeightUnit.*` 的 `text` 绑定渲染成空白（历史记录重量、称重卡片数字+单位、食材卡"单价（…）"标签），其他控件正常；开关开/关都一样。

权威依据：Qt 官方博客 *Implicit Imports vs. QML Modules in Qt 6*（Ulf Hermann）——"You generally don't have to import the module a QML file belongs to itself" 仅成立在文件与 qmldir 同目录时；并明确警告「同一类型名经命名模块导入是 singleton、经同目录隐式导入却是普通类型」。修法即博客方案 3：**每个文件都显式 import 自己的模块**。

## 排查：OTA 拉起自动登录的账号与重启不一致（root 家目录凭据）

现象：OTA 刷写后拉起的实例自动登录 `260100001`，正常重启（sjwu）不自动登录。

- 另发现：`/etc/systemd/system/smartscale.service` 的 `ExecStart=/home/sjwu/SmartScale/start_app.sh` **该脚本不存在**，且单元 disabled → 走 systemd 路径本来也起不来。
- 文件格式坑：键名是 `password`（不是 `pass`），值是 `@ByteArray(...)` 包装（因为 `m_pendingPassword.toUtf8().toBase64()` 返回 QByteArray，QSettings 按 ByteArray 变体序列化）；解码括号内 base64 才是明文。读完 `.toString()` 自动转换，功能正常。
- 密码来源优先级：启动路径 `autoLogin()` **只读 last_login.conf，完全不看 login_history.json**；`loginByHistory()`/`hasRememberedPassword()` 才是「history 的 password 优先 → 回退 last_login.conf（且要求 userCode 相同）」。实测两份 login_history.json 都没有 password 字段。

- 安全：`last_login.conf` 权限 644（本机任意用户可读，base64 可逆）；`build/data/smartscale.log` 原样打印登录报文含明文密码；多个实例共写同一个日志文件，排查时时间戳会交错。
